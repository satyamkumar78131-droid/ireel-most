Get ireel as a file & APK

This whole app is one single file. Download it, keep it on your phone, and open it in Chrome any time — no internet needed after download.

Turn the file into an APK

  1. Tap the download button above and save ireel.html.
  2. Open the free AppsGeyser APK Maker in Chrome and choose the HTML option.
  3. Upload the ireel.html file, set the app name to ireel, and tap Create.
  4. Download the APK it gives you and install it (Android may ask you to allow “Install unknown apps” for Chrome — allow it just for this install).

Note: on its own, this file keeps posts on this device while the app is open. Turn on the Shared feed above (free Supabase backend) and everyone's posts, reels, stories, likes and comments sync into one feed that all users see.

Make the link permanent (free hosting)

A share link can expire. Host the downloaded file free instead, so one link works forever — and nothing is erased: everyone's shared posts live in Supabase, not inside the file.

  1. Tap Download ireel.html file above and save the file on your phone.
  2. Easiest — Netlify Drop: open app.netlify.com/drop, sign up free, and drop the ireel.html file in. You instantly get a permanent link (like yourname.netlify.app) to share with everyone.
  3. Or GitHub Pages: sign up free at github.com, create a public repo named yourname.github.io, and upload the file renamed to index.html — your link becomes https://yourname.github.io.
  4. Whenever you download a newer ireel.html later, just upload it to the same place again — the link stays the same and all shared posts, likes and comments stay untouched.

Never paste the service_role / Secret key — it is secret. Only the anon public / Publishable key belongs in an app.

This app already has the Project URL and Publishable key built in, so the shared feed connects automatically for everyone who opens it. Just make sure the SQL above (step 2) has been run once in your Supabase project — without it, the feed cannot load. The same SQL also creates the stories table, so everyone's stories show in the story row for 24 hours — and the profiles, follows and messages tables, so every user's account profile and follow counts sync for everyone, and direct messages sync privately — the messages policies check the signed-in account's own identity, so a thread can only be read by its sender and recipient, never by other users. Profiles never store email addresses; emails stay inside Supabase Auth only. (Real password accounts use Supabase Auth: enable Email signups in Authentication → Providers if they are off.) Running the SQL again is safe: it only creates what is missing and never deletes any data.
